1. 💳 결제 문제 (In-App Purchase)

수정완료 StoreKit 2 실제 결제 연동

파일: SubscriptionView.swift — purchasePlan()

문제: 기존 코드가 DispatchQueue.main.asyncAfter로 1.2초 후 즉시 Pro 활성화하는 데모 코드였습니다. 실제 Apple 결제 없이 구독이 활성화되어 심사 리젝 대상입니다.

수정: Product.products(for:)로 상품 로드 → product.purchase()로 실제 결제 → .verified 검증 후에만 Pro 활성화하도록 변경.

수정완료 앱 시작 시 트랜잭션 리스너 추가

파일: NaelmApp.swift — RootView

문제: 외부에서 발생하는 구독 갱신/취소/환불을 감지하지 못했습니다.

수정:

  • Transaction.updates 리스너를 앱 시작 시 등록하여 실시간 구독 상태 변경 감지
  • Transaction.currentEntitlements로 앱 시작 시 현재 구독 상태 동기화
  • 구독 만료/취소 시 자동으로 Pro 비활성화 (lifetime 코드 제외)
수정완료 구독 취소를 Apple 구독 관리로 변경

파일: MyPageView.swift

문제: 앱 내에서 직접 profile.isPro = false로 구독을 취소하고 있었습니다. Apple 자동갱신 구독은 반드시 Apple의 구독 관리 시스템을 통해 취소해야 합니다 (Guideline 3.1.1).

수정: "구독 취소" → "구독 관리"로 변경하고, https://apps.apple.com/account/subscriptions 페이지로 연결.

권장 서버 사이드 영수증 검증

현재 클라이언트에서만 Transaction 검증을 수행합니다. 프로덕션 환경에서는 App Store Server API 또는 App Store Server Notifications V2를 통한 서버 사이드 검증을 권장합니다. 초기 출시에는 클라이언트 검증만으로도 심사 통과 가능하지만, 구독 사기 방지를 위해 향후 구현을 권장합니다.

2. 🔐 로그인 & 회원가입 문제

양호 Sign in with Apple 구현

Sign in with Apple이 올바르게 구현되어 있습니다:

  • ✅ ASAuthorizationAppleIDProvider 기반 로그인
  • ✅ Keychain에 userIdentifier 저장/복원
  • ✅ credential 상태 확인 (revoked/notFound 처리)
  • ✅ 게스트 로그인 옵션 제공
  • ✅ 계정 삭제 기능 (Guideline 5.1.1 준수)
  • ✅ 로그아웃 기능
권장 게스트 → Apple 계정 연동

게스트로 시작한 사용자가 나중에 Sign in with Apple로 전환할 때 기존 학습 데이터를 마이그레이션하는 흐름이 없습니다. 출시 후에도 추가 가능하지만, 게스트 사용자가 데이터 손실 없이 계정을 업그레이드할 수 있는 기능을 권장합니다.

3. 📝 사업자등록 & 법적 요건

필수 사업자등록증 / 통신판매업 신고

유료 구독 앱을 출시하려면 다음이 필요합니다:

  • 사업자등록: 개인사업자 또는 법인사업자 (세무서 신고)
  • 통신판매업 신고: 관할 구청에 신고 (사업자등록증 필요)
  • D-U-N-S 번호: Apple Developer 조직 계정 시 필요 (개인 계정이면 불필요)
  • 세금 계약: App Store Connect > 계약, 세금, 뱅킹에서 유료 앱 계약 체결

⏱ 소요 시간: 사업자등록 1~2일, 통신판매업 신고 3~7일, D-U-N-S 번호 발급 최대 30일

필수 이용약관 & 개인정보처리방침 페이지

현재 코드에서 다음 URL로 연결하고 있습니다:

  • https://toeigo.notion.site/terms — 이용약관
  • https://toeigo.notion.site/privacy — 개인정보처리방침

반드시 실제 페이지를 생성해야 합니다. 페이지가 없으면 심사 리젝됩니다.

개인정보처리방침에 반드시 포함할 내용:

  • 수집하는 개인정보 항목 (Apple ID, 이름, 학습 데이터)
  • 수집 목적 (서비스 제공, 학습 진도 관리)
  • 보관 기간 및 파기 방법
  • 제3자 제공 여부 (CloudKit 사용 고지)
  • 이용자의 권리 (삭제 요청 등)
  • 연락처 (이메일, 대표자명)

이용약관에 반드시 포함할 내용:

  • 자동갱신 구독 조건 및 가격
  • 갱신/취소 방법 안내
  • 환불 정책 (Apple 환불 정책 안내)
  • 서비스 이용 제한 사항

4. 🍎 Apple 심사 가이드라인 준수 사항

수정완료 ATT (App Tracking Transparency) 제거

파일: NaelmApp.swift

문제: ATTrackingManager.requestTrackingAuthorization을 호출하지만 실제로 추적 기능이 없습니다. 추적하지 않으면서 ATT 팝업을 표시하면 Guideline 5.1.2 위반으로 리젝될 수 있습니다.

수정: ATT import 및 권한 요청 코드를 제거했습니다. Info.plist에 NSUserTrackingUsageDescription이 있다면 그것도 제거하세요.

양호 Guideline 3.1.1 — 인앱결제
  • ✅ 구매 복원 버튼 존재
  • ✅ 자동갱신 구독 조건 고지 (footnote)
  • ✅ 이용약관/개인정보처리방침 링크
  • ✅ 가격 표시
양호 Guideline 5.1.1 — 계정 삭제

마이페이지에 계정 삭제 기능이 구현되어 있으며, 2단계 확인을 거칩니다. 모든 관련 데이터(UserProfile, LearningProgress, UserActivity, MonthlyScore, BookmarkedWord, Friendship)를 삭제합니다.

5. 🔧 추가 코드 개선 권장사항

참고 코드 입력(Redeem) 기능 검토

MyPageView에 SHA256 해시 기반 코드 입력으로 영구 구독을 부여하는 기능이 있습니다. 이 기능 자체는 심사에서 리젝되지 않지만, App Store 외부 결제 우회로 해석될 여지가 있으므로:

  • 심사 시 "개발자 내부 테스트/프로모션 코드"임을 심사 메모에 명시
  • 또는 Apple의 Offer Codes (App Store Connect에서 생성)를 사용하는 것을 권장
참고 CloudKit 컨테이너 ID 설정

Naelm.entitlements에서 icloud-container-identifiers가 빈 배열입니다. CloudKit 동기화를 사용하려면 App Store Connect에서 CloudKit 컨테이너를 생성하고 ID를 설정해야 합니다.

참고 랭킹 뷰 mock 데이터

RankingView에서 하드코딩된 mock 랭킹 데이터를 사용하고 있습니다. 출시 시 이대로 두면 사용자가 혼동할 수 있습니다. "샘플 데이터"임을 명시하거나, 실제 CloudKit 기반 랭킹으로 교체하는 것을 권장합니다.
