1. 현재 알고리즘 구조 개요

Naelm은 두 개의 독립적인 알고리즘이 직렬 파이프라인을 이루고 있습니다. 알고리즘 ①이 오늘 풀 문항을 선정하고, 알고리즘 ②가 결과에 따라 개인별 복습 간격을 조정합니다.

①

덱 선정 (Deck Selection)

CardViewModel.loadDeck() / QuizViewModel.loadQuiz()
사용자의 estimatedLevel(현재수준) 40% + targetScore(목표수준) 60%로 비율 구성. 비숙달(isMastered=false) 항목 중 frequencyLevel로 필터링.

⟳

세션 실행 중

단어 스와이프 결과 → pendingVocab, 문법 퀴즈 결과 → pendingGrammar 에 메모리 적재. DB는 세션 종료까지 미반영.

②

SM-2 계산 (Difficulty Adjustment)

SpacedRepetitionService.calculate()
quality 0–5 입력 → easeFactor / interval / nextReviewDate 갱신. 세션 종료(endSession) 시 일괄 DB 반영.

2. 알고리즘 ①: 난이도 선정 — 현황 & 문제점
현재 선정 로직
1

숙달 항목 제외

isMastered == true인 항목은 덱에서 완전 제외

2

비율 분배

현재 수준 40% + 목표 수준 60% (각 레벨 랜덤 셔플)

3

부족분 채우기 + 중복 제거

일일 목표 수(dailyGoal)까지 전체 풀에서 랜덤 보충

🐛 발견된 문제점 Critical
문제 현재 코드 영향
🔴 SRS 복습 대상 무시 fetchDueVocabulary() / fetchDueGrammar()가 덱 구성에 전혀 사용되지 않음 복습 예정일이 지난 항목이 우선 노출되지 않아 SM-2 효과가 무력화됨
🟡 세션 워밍업 없음 카드가 완전 랜덤 셔플됨 세션 초반부터 고난이도 문제 노출 → 동기 저하, 오답 편향
🟡 최근 오답 항목 미반영 직전 세션 오답이 다음 세션 덱 비율에 영향 없음 동일 약점이 반복 노출되지 않음

3. 알고리즘 ②: SM-2 난이도 조정 — 현황 & 문제점
SM-2 핵심 공식
EaseFactor 업데이트
EF' = EF + (0.1 − (5−q) × (0.08 + (5−q) × 0.02))
// EF 최솟값: 1.3 | q: 0–5 품질 점수

Interval 계산
repetitions=1 → interval=1일
repetitions=2 → interval=6일
repetitions≥3 → interval=round(prevInterval × EF)

숙달(Mastery) 판정
streak ≥ 5 AND easeFactor ≥ 2.5
🐛 발견된 버그 & 논리적 결함 4개
버그/결함 현재 코드 개선 방향
🔴 Mastery 우회 버그 endSession()에서 knewIt=true이면 즉시 isMastered=true 설정 → streak≥5 조건 우회됨 endSession에서 직접 isMastered 설정 코드 제거, applyResult()에만 위임
🔴 Quality 이진화 단어: knewIt ? 4 : 1, 문법: isCorrect ? 4 : 1로만 매핑 — SM-2의 0–5 범위 미활용 응답 시간, 힌트 사용 여부를 반영한 0–5 세분화 품질 계산
🟡 망각 곡선 미적용 장기 미복습 항목(lastReviewedAt이 매우 오래됨)도 기존 easeFactor 그대로 사용 30일 이상 미복습이면 easeFactor 패널티 적용 후 재복습 유도
🟡 interval=0 실패 재복습 미활용 실패 시 nextReviewDate = 10분 후이지만, 덱 선정 로직이 이를 조회하지 않음 덱에 SRS 복습 대상을 우선 포함
🚀
4. 개선된 알고리즘 설계
4-1. Quality 세분화 (이진 → 0–5) 구현 완료

응답 시간과 힌트 사용 여부를 결합하여 SM-2가 설계된 대로 0–5 품질 점수를 산출합니다.

단어 카드 — Quality 매핑
알고 있음 + 빠른 응답(≤5초) → quality = 5
알고 있음 + 보통 응답(5~10초) → quality = 4
알고 있음 + 느린 응답(>10초) → quality = 3
모름 + 느린 응답 → quality = 1
모름 + 빠른 응답(찍기 의심) → quality = 0

문법 퀴즈 — Quality 매핑
정답 + 빠른 응답(≤타이머50%) → quality = 5
정답 + 보통 응답 → quality = 4
정답 + 느린 응답(타이머 거의 소진) → quality = 3
오답 (응답함) → quality = 1
타임아웃 / 모르겠다 → quality = 0
4-2. 덱 구성 개선 — SRS 복습 우선순위 구현 완료
!

① SRS 복습 대상 우선 편입 (최대 50%)

fetchDueVocabulary()로 오늘 복습 예정 항목을 가져와 덱 앞쪽에 배치. 복습 항목이 50%를 초과하면 잉여분은 다음 세션으로 이월.

2

② 워밍업 구간 (첫 2~3문제)

현재 수준(estimatedLevel)보다 1단계 낮은 항목 또는 streak≥3 이상인 항목으로 구성. 세션 초반 자신감 유지.

3

③ 메인 덱 (기존 40%/60% 로직 유지)

현재 수준 40% + 목표 수준 60%. SRS 복습 + 워밍업 이후 잔여 슬롯에 배치.

4-3. 망각 곡선 리셋 로직 구현 완료

에빙하우스 망각 곡선에 따르면 30일 이상 미복습이면 기억 보유율이 급감합니다. 장기 미복습 항목에는 easeFactor 패널티를 적용합니다.

망각 패널티
daysSinceReview ≤ 30일 → 패널티 없음
31 ~ 60일 → EF × 0.85 (15% 감소)
61 ~ 90일 → EF × 0.70 (30% 감소)
> 90일 → EF = 1.3 (최솟값으로 리셋)
// 리셋 후 repetitions도 0으로 초기화하여 1일→6일→N일 재시작
4-4. Mastery 버그 수정 구현 완료
Before (버그)
endSession에서 knewIt=true이면 즉시 isMastered=true
streak 조건(≥5) 우회됨
단 1번 알았다고 해도 숙달 처리
SRS 복습 대상에서 영구 제외
After (수정)
endSession에서 직접 isMastered 설정 코드 제거
applyResult()의 streak≥5 && EF≥2.5 조건만 사용
단어도 반복 학습 후 단계적 숙달
markedForReview 로직은 그대로 유지

5. Apple Intelligence 도입 가능성 검토
✦
Apple Intelligence Integration
iOS 18.1+ · On-Device NLP · Privacy-First

Apple Intelligence는 iPhone에서 온디바이스로 동작하는 AI 시스템으로, 민감한 학습 데이터를 서버에 전송하지 않고도 개인화된 경험을 제공할 수 있습니다. 아래는 Naelm에 적용 가능한 기능별 실현 가능성을 분석한 결과입니다.

📝
Writing Tools — 예문 생성
사용자의 약점 단어로 맥락 예문을 즉석 생성. NSWritingToolsCoordinator API.
실현 가능성 80%
🧠
Foundation Models — 적응형 힌트
오답 패턴 분석 후 개인화 힌트 텍스트 생성. iOS 26 Foundation Models framework.
실현 가능성 65% (iOS 26 필요)
🗣️
Speech NLP — 발음 평가
SFSpeechRecognizer + NaturalLanguage로 단어 발음 정확도 측정, quality 점수 반영.
실현 가능성 70%
⏱️
CoreML — 응답 패턴 예측
사용자 응답 시간 패턴을 학습해 최적 복습 간격을 SM-2에 보정값으로 추가 제공.
실현 가능성 55% (데이터 축적 필요)
📊
Smart Summaries — 학습 리포트
세션 종료 후 약점 패턴을 한국어 요약 생성. Writing Tools Summarize 기능 활용.
실현 가능성 85%
🎯
Siri Intent — 학습 시작 자동화
AppIntents로 "나엘름에서 오늘 단어 복습해줘" 단축어 제공. 알림 연동.
실현 가능성 90%
⚠️ 도입 시 주의 사항
  • 기기 호환성: Apple Intelligence는 iPhone 15 Pro / iPhone 16 이상, iOS 18.1+ 필요. 미지원 기기 fallback 로직 필수.
  • Foundation Models API: 현재 iOS 26 개발자 베타에서 공개 예정. 안정적 GA 릴리스 전 프로덕션 사용 지양.
  • Writing Tools: UITextView / NSTextView 기반 뷰에서만 네이티브 동작. SwiftUI TextEditor로 연동 가능.
  • 온디바이스 처리: 클라우드 AI 대비 모델 규모 제한. 복잡한 추론보다 텍스트 요약/생성에 적합.
  • 개인정보 우위: 학습 데이터(오답/취약 단어 등)가 디바이스 외부로 유출되지 않는 것이 최대 장점.
✅ 단기 권장 도입 항목

현재 iOS 18.x에서 즉시 구현 가능하며 학습 경험 향상 효과가 높은 항목:

  1. AppIntents (Siri 단축어) — 복습 알림 자동화, "오늘 복습 단어 몇 개?" 인텐트
  2. Smart Summaries (Writing Tools) — 세션 종료 리포트 자동 요약
  3. SFSpeechRecognizer — 단어 발음 체크 모드 (선택 기능)
