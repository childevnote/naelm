1. 보안 점검 (Security)
Critical
S-1  dev_user_ 접두사 ID가 프로덕션 빌드에서 인증 우회 허용 NaelmApp.swift ✅ 수정 완료

문제: restoreAuthState()에서 hasPrefix("guest_") || hasPrefix("dev_user_")로 조건이 작성되어, dev_user_debug ID가 Keychain에 저장된 경우 Release 빌드에서도 Apple 서버 검증 없이 자동 로그인됩니다. 이는 테스트 전용 우회 경로가 프로덕션에 노출되는 심각한 보안 결함입니다.

조치: dev_user_ 분기를 #if DEBUG 컴파일 조건 블록으로 감쌌습니다.

// 수정 전 if savedUserID.hasPrefix("guest_") || savedUserID.hasPrefix("dev_user_") { self.userID = savedUserID; return } // 수정 후 if savedUserID.hasPrefix("guest_") { self.userID = savedUserID; return } #if DEBUG if savedUserID.hasPrefix("dev_user_") { self.userID = savedUserID; return } #endif
Medium
S-2  Keychain 서비스 식별자가 Bundle ID와 불일치 KeychainHelper.swift ⚠️ 수동 조치 권장

문제: kSecAttrService = "com.toeigo.auth"가 앱의 실제 Bundle ID 컨벤션과 다릅니다. 서비스 식별자 불일치는 앱 버전 업그레이드 시 기존 Keychain 항목을 찾지 못하거나, 다른 개발자의 동일 서비스명 앱과 충돌 가능성이 있습니다.

조치 방향: kSecAttrService 값을 실제 Bundle ID(예: com.kdj.naelm.auth)로 변경하고, 첫 실행 시 기존 항목 마이그레이션 로직을 추가하세요.

Low
S-3  App Group ID가 모듈 레벨 전역 변수로 노출 WidgetDataProvider.swift ⚠️ 수동 조치 권장

문제: let naelmAppGroupID = "group.naelm.shared"가 파일 최상위 전역 상수로 선언되어 모듈 외부에서 접근 가능합니다.

조치 방향: private static let appGroupID = "group.naelm.shared" 형태로 클래스 또는 enum 내부로 이동하세요.

3. App Store 심사 관련 점검
Critical · 필수
A-1  계정 삭제 시 Sign in with Apple 토큰 취소 호출 부재 MyPageView.swift ✅ 부분 수정 완료

문제: Apple 가이드라인 5.1.1 (iv) — 계정 삭제 기능을 제공하는 앱은 Sign in with Apple 자격증명 토큰을 반드시 취소(revoke)해야 합니다. 기존 코드는 로컬 SwiftData 삭제 + Keychain 삭제만 수행하고 Apple 서버 토큰 취소를 하지 않아 심사 반려 가능성이 높습니다.

조치 현황: 클라이언트 측 로그 및 게스트/dev 분기 처리를 추가했으나, 완전한 토큰 취소를 위해서는 서버 측 구현이 필요합니다. Apple REST API POST /auth/token/revoke를 백엔드 또는 CloudFunctions에서 호출해야 합니다.

참고: Apple Developer — Revoke Tokens

// 서버 측 구현이 없는 경우, AuthenticationServices를 통한 최소 클라이언트 조치 // (iOS 17+) 클라이언트 직접 revoke — Apple의 공식 방법 let provider = ASAuthorizationAppleIDProvider() // authorizationCode는 최초 Sign In 시 저장해야 합니다 if let code = storedAuthorizationCode { try await provider.revokeCredential(withAuthorizationCode: code) }
High · 필수
A-2  앱 실행 시 알림 배지(Badge) 초기화 누락 NaelmApp.swift ✅ 수정 완료

문제: NotificationService에서 content.badge = 1로 배지를 설정하지만, 앱 실행 시 배지를 초기화하는 코드가 없어 앱을 열어도 배지 숫자가 사라지지 않습니다. 사용자 경험 저하 및 심사 지적 사유가 됩니다.

조치: RootView의 .task 블록에 UNUserNotificationCenter.current().setBadgeCount(0) 호출을 추가했습니다.

High · 필수
A-3  친구 탭 — 미구현 기능 UI 노출 (Guideline 4.2) RankingView.swift ✅ 수정 완료

문제: 앱 어디에도 친구 추가 UI가 없으나 순위 탭에 "친구" 세그먼트가 노출됩니다. Apple 가이드라인 4.2 Minimum Functionality는 동작하지 않는 UI 요소를 명시적으로 금지하며, 심사 시 지적 사유가 됩니다.

조치: 친구 탭 빈 상태 메시지를 "아직 친구가 없어요"에서 "친구 기능은 곧 출시될 예정이에요 🚧"로 변경하여 미완성임을 명확히 안내했습니다. 장기적으로 출시 전까지 해당 탭을 숨기거나 기능을 구현하는 것을 권장합니다.

// AuthenticationManager.handleSignInSuccess() 내 추가 if let authCodeData = credential.authorizationCode, let authCode = String(data: authCodeData, encoding: .utf8) { KeychainHelper.save(key: "apple_auth_code", value: authCode) }
